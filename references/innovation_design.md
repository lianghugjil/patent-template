# 创新构思：从技术问题到可专利方案

> 本文件是**写作之前**那一环的判据，**且只在一种情况下启用**：
> 用户只给了方向、问题或效果诉求，手上没有具体方案。
> 只要用户已经说出方案（有结构、有步骤、有原理，哪怕口语化），**本文件整份跳过**——
> 那是他的发明，我照写；我不是替他重新发明一次。
> **五册结构、版式、体检脚本一律不动。** 构思是前置，不是新增一册。

---

## 0. 先划边界（写报告前必读，别越过）

**启用条件（不符合就别开这一环）：**

| 用户给的 | 本文件 |
|---|---|
| 具体方案（结构/步骤/原理/参数） | **不启用**。照他的方案写；补的公知细节逐条报账 |
| 只有方向、问题、效果诉求 | **启用** |
| 有方案但明显硬伤 | **仍按他的方案写** + 在交付说明点出问题；改不改由他定 |
| 他明说"你看着办/帮我优化" | 启用，但新加特征要先说一句再落进正文 |

**能做到的：**

| 能做 | 判据 |
|---|---|
| 产生方案族 | 同一问题给出 3~8 个可选方向，不是一个"标准答案" |
| 筛方向 | 用进化法则判断哪条是"进化必然"，创造性更站得住 |
| 可专利性初判 | 法 22 条 2/3/4 款逐项打分，并给理由 |
| 权项布局 | 方案族 → 独权 + 至少 3 级退守从权 |
| 风险分级 | 高/中/低，写清依据 |

**不能承诺的（谁承诺谁在骗人）：**

| 不能 | 为什么 |
|---|---|
| **保证授权** | 授权是审查员基于检索后的自由裁量；工具只能提高完备度 |
| **保证新颖性** | 没有检索就不能断言"新"；只能写"相对已知材料未发现相同方案" |
| **保证创造性** | 创造性以"最接近的现有技术"为基准，基准本身来自检索 |
| **零侵权** | 侵权是**法律判断**，不是技术判断：① 地域性（中国专利只在中国境内有效）② 时间性（只看有效期内）③ 要看是否落入他人**权利要求**保护范围（全面覆盖 + 等同原则）。工具能做 FTO 风险筛查，不能出法律结论 |

**报告首行的强制标注**（二选一，不许留空）：

```
检索状态：已检索（检索式见 §7）        ← 有网络、跑过检索
检索状态：未检索，仅供讨论              ← 无网络 / 未做检索
```

> 写了"未检索"的报告，**全篇不得出现**"具有新颖性""具备创造性""可以授权""零侵权"这类结论句，
> 只能写"未发现相同方案""待检索验证"。`make_idea_report.py --check` 会把这类越界句判 ERROR。

## 1. 输入：最小可用信息

一句话技术问题也能开工，但下面四项**缺的要在报告里显式假设**，不许默默编：

| 项 | 例 |
|---|---|
| 技术问题 | "管道内壁结垢无法在不停止输水的情况下清理" |
| 现有方案 | "目前靠停水人工清掏 / 化学清洗" |
| 约束 | 不能停水、不能加化学药剂、管径受限、成本、防爆 |
| 输出目标 | 发明还是实用新型；结构 / 方法 / 算法 / 系统 |

假设写成一行：「假设：管径 200~600 mm，输水压力 ≤0.6 MPa，无外部电源。」后面所有推演受这些假设约束。

---

## 2. 第一步：定义技术系统 + S 曲线定位

**技术系统 = 一项功能 + 承担它的子系统集合。**

功能句写成 **动词 + 对象 + 约束**：

```
在【约束】条件下，对【对象】实现【功能】。
例：在不停止输水、不投加药剂的条件下，对管壁附着物实现持续剥离。
```

**S 曲线四期判定**（决定后面该用哪类工具）：

| 期 | 特征 | 该往哪推 | 主要工具 |
|---|---|---|---|
| 婴儿期 | 功能勉强成立、可靠性差 | 补完备性 | 完备性法则、物场分析 |
| 成长期 | 功能成立、参数在优化 | 解矛盾、提参数 | 矛盾矩阵 + 40 原理 |
| 成熟期 | 参数逼近物理极限、同质化严重 | 向超系统 / 向微观级跃迁 | 进化法则 6/7、剪裁、IFR |
| 衰退期 | 被替代技术挤压 | 换原理，不是改参数 | 科学效应库、跨领域移植 |

判据（能查就给数，查不到就写"按经验判断"）：同族专利年度申请量是否走平、关键参数是否逼近理论上限、是否已有替代原理出现。

---

## 3. 第二步：建进化树

树有三个维度，**至少画两个**：

- **时间维**：同一问题历代方案（人工 → 半自动 → 自动；机械 → 电气 → 智能）
- **层级维**：超系统 / 系统 / 子系统（整机 → 模块 → 元件）
- **分支维**：并行技术路线（接触式 vs 非接触式；主动 vs 被动）

**每个节点只记四项**（多了没人看）：

```
方案名 | 关键参数 | 解决了什么矛盾 | 遗留什么缺陷
```

**要找的是两样东西：**

1. **主干**——多数方案都沿这条走，说明它是"进化必然方向"，沿它出方案，创造性论证最容易站住。
2. **断头分支**——走到一半没人继续的分支。断头处往往就是空白区，也是最容易做出"预料不到的效果"的地方。

> 什帕科夫斯基那套的核心不是画得漂亮，而是**用专利信息当树的节点来源**：谁的方案、什么时候、解决什么、
> 参数到哪。所以能检索时，节点尽量带公开号；不能检索时，节点写"据已知材料"，并标"未核实"。

---

## 4. 第三步：把问题压成一个矛盾

写不出矛盾，说明问题还没定义清楚。两种：

| 类型 | 形态 | 处理 |
|---|---|---|
| **技术矛盾（TC）** | 改善 A，恶化 B（例：提高清洗力 → 损伤管壁） | 查矛盾矩阵 → 40 发明原理 |
| **物理矛盾（PC）** | 同一参数既要大又要小（例：工具既要贴壁刮削，又要不接触管壁） | 用**分离原理**：时间分离 / 空间分离 / 条件分离 / 整体部分分离 |

优先处理物理矛盾——它往往对应更强的创造性（克服技术偏见、非线性跃变都从这里出来）。

---

## 5. 第四步：按问题类型选 TRIZ 工具

**不要一次把所有工具都上一遍**，按症状选一个主工具 + 一个辅工具：

| 症状 | 主工具 | 产出 |
|---|---|---|
| 想不出方向 | 进化法则（下表）+ 进化树 | 3~5 个方向 |
| 两难取舍 | 矛盾矩阵 + 40 发明原理 | 具体手段 |
| 功能不足 / 有有害作用 | 物场分析 + 76 标准解 | 换场、加物质、拆场 |
| 系统太复杂、成本高 | 剪裁（Trimming） | 去掉部件仍保功能 |
| 想定极限目标 | 理想最终结果（IFR） | 判断还有多少改进空间 |
| 缺物理效应 | 科学效应库 | 跨领域移植 |
| 久攻不下 | ARIZ | 系统化求解 |
| 团队共创、要收敛 | SIT / USIT | 封闭世界 + 限定技巧 |

**进化法则（八条，推方向时逐条过一遍）：**

1. **完备性**：系统必须能独立完成功能（缺动力/传动/执行/控制哪一环？）
2. **能量传递**：能量流越直接、越可控越好（有没有多一次转换？）
3. **协调性**：参数、节奏、形状、材料相互协调（配合处是否失配？）
4. **理想化**：向"功能仍在、实体趋零"逼近
5. **动态化**：刚性 → 铰接 → 柔性 → 自适应 → 场
6. **向微观级进化**：宏观机构 → 微结构 → 分子/场作用
7. **向超系统进化**：把系统并入更大的系统，用外部资源
8. **子系统不均衡进化**：最短板决定整体，先补短板

> 每条法则至少产出一个候选，**并写明它对应哪个矛盾、预期什么效果**。写不出效果的，删掉。

---

## 6. 第五步：生成方案族（要"族"，不是"一个方案"）

**数量：3~8 个。** 结构如下，每个方案一张卡片：

```
方案 N：<名字>
原理：沿哪条进化法则 / 哪个发明原理
结构或步骤：3~5 句，能画出示意图
解决的矛盾：TC 或 PC 的具体内容
预期效果：定性 + 可量化的指标（有数据来源就写来源）
实施难度：低 / 中 / 高（加工、成本、可靠性）
```

**必须包含两类极值方案**（这是提高命中率的关键）：

- 至少 **1 个低风险**：接近现有技术，改动小，容易授权，适合先占位（实用新型更快）。
- 至少 **1 个高创造性**：可能被质疑，但若论证成立价值大（发明，需备好"预料不到的效果"）。

> 只给"一个最优解"是最常见的失败模式：一旦检索命中，整份材料全废；给了族，命中一个还能换一个。

---

## 7. 第六步：检索校正（做不了的必须承认）

**检索三要素：**

| 要素 | 怎么做 |
|---|---|
| 关键词 | 中英双语 + 同义词 + 上位词 + 下位词（例：清洗/除垢/剥离/cleaning/fouling/scale removal） |
| 分类号 | IPC / CPC，至少给主组（例：B08B 9/00 管道清洗） |
| 引证 | 找到一篇最接近的，看它的被引与施引，滚雪球 |

**结果怎么用：**

- **命中相同方案** → 该方案降级（改成从权、或换方向），报告里写"已被公开，仅作对照"。
- **命中相近方案** → 保留，但必须在"区别技术特征"里写清差异，并说明该差异带来的效果。
- **未命中** → 标"待验证"，**不等于**"具有新颖性"。

**检索 ≠ FTO。** FTO（自由实施）要单独做，且要看目标市场、专利有效期、权利要求比对。报告里要把这句写出来，别让用户误以为"没检索到就是零侵权"。

**未检索是一道门禁，不是一句免责声明。** `--check` 对「检索状态：未检索」出的是 WARN，
不是通过；三性都写「待验证」时再加一条 WARN，退出码为 2。这稿只能叫「待检索稿」：

- 五册可以写，交付口径必须写明"创造性结论未验证"，不得宣称具备新颖性/创造性。
- `--export` 抽交底时会在文件尾自动落一条注释，把这个事实钉在写稿输入件上。
- 检索一旦补上，回来改底稿的「检索状态」与三性，再复跑 `--check`——**不要只在对话里口头补一句**。

> 这条门禁是补出来的：早前版本把"未检索"当成"已显式声明、合规"直接记 ✅，
> 结果零检索的案子一路绿灯写完全部五册，创造性论证全靠编的数据撑着。

## 8. 第七步：可专利性初判（法 22 条三性 + 三步法）

逐项打分，每项必须给理由。**没有检索时，新颖性/创造性只能打"待验证"。**

### 新颖性（法 22.2）

单独对比：是否有一篇现有技术**公开了全部技术特征**。
- 有一篇全部公开 → 无新颖性
- 没有 → 相对新颖（若已检索）/ 待验证（若未检索）

### 创造性（法 22.3，三步法，必须按顺序走）

1. **确定最接近的现有技术**（同领域、解决同样问题、技术特征最接近的一篇）
2. **确定区别特征 + 实际解决的技术问题**（区别特征在本方案里起什么作用，据此重新表述技术问题）
3. **判断是否显而易见**（现有技术整体上是否有启示；是否只是常规手段的简单叠加）

**创造性论证的四类弹药**（成稿时写进"有益效果"，这里先预备）：

- **预料不到的技术效果**（超出线性外推）
- **非线性跃变**（参数跨过某阈值性能突变）
- **克服技术偏见**（本领域普遍认为不该这么做，而本方案这么做并且有效）
- **多重效果协同**（两个特征合起来的效果大于各自之和）

### 实用性（法 22.4）

能制造（材料/工艺可行）、能使用（可重复实施）、能产生积极效果（不是纯理论）。

### 打分表（报告里必须有）

| 方案 | 新颖性 | 创造性 | 实用性 | 综合风险 | 依据 |
|---|---|---|---|---|---|
| 方案 1 | 待验证 | 中 | 高 | 中 | 与最接近方案的区别在 X，效果提升 Y |
| … | | | | | |

## 9. 第八步：方案族 → 权项梯度

**一个方案对应一组权项，不要把多个方案塞进一个独权。**

```
独权 1：覆盖核心（最宽，只写必要技术特征）
  └ 从权 2：加限定 A（第一级退守）
      └ 从权 3：加限定 B（第二级退守）
          └ 从权 4：加限定 C（第三级退守）
```

**至少 3 级退守**。理由是答复审查意见时，每退一级都要有说明书支持，事先不布好，答复期加不进去（法 33 条）。

尺寸与参数仍然遵守 SKILL.md §5.1：**只划线不定点**（相对量、单侧边界、区间+优选），禁公称尺寸+公差代号。

## 10. 输出物：内部构思底稿（不外发）

**这份底稿是内部件，不是交付物。** 不发给用户、不进交付包、不贴进对话正文。
用户拿到的永远只有五册；底稿只用来把路线定清楚。

与五册的接口只有两处：**选中的方案**（其"技术问题 / 技术方案 / 有益效果"注入说明书"发明内容"），
以及**权项梯度骨架**（照抄成从权层级，但不带"风险等级/退路"这类标注）。
格式、标号、附图、体检全部照旧。

底稿骨架用脚本生成，别手搓：

```bash
python scripts/make_idea_report.py --problem "一句话技术问题" -o _内部_构思报告.md
python scripts/make_idea_report.py --check _内部_构思报告.md          # 写完自检，ERROR 必须清零
python scripts/make_idea_report.py --export _内部_构思报告.md --pick 3 -o 交底.md   # 抽纯技术交底
```

`--export` 会剥掉方案类型、实施难度、矛盾表述与检索结论，只留技术本体；
产出前再做一次泄露扫描（方法名 / 方案编号 / 检索痕迹 / 待填），命中即拒绝落盘。

**必含十节**（脚本按这个校验）：

1. 检索状态与假设
2. 技术系统与 S 曲线定位
3. 进化树
4. 关键矛盾（TC / PC）
5. TRIZ 工具与推演
6. 候选方案族（≥3 个，含低风险与高创造性各 ≥1）
7. 检索校正
8. 可专利性初判（三性 + 三步法 + 打分表）
9. 权项梯度（≥3 级退守）
10. 结论与下一步建议

## 11. 红线（违反即不合格）

0. **用户已有方案却另起一套** → 最严重的一条。他的方案是发明本体，我只能翻译、补细节、划范围、配从权；
   把独权里他没提过的结构塞进去，等于换了一件专利，署的还是他的名。补的公知细节必须逐条报账。
1. **未检索就写"具有新颖性/创造性"** → 越界，必须改成"未发现相同方案，待检索验证"。
2. **编造对比文件号 / 公开号** → 绝对禁止。检索不到就写"未检索"，不许造一个像真的号。
3. **承诺授权或零侵权** → 绝对禁止，只能给风险等级。
4. **只给一个方案** → 不合格，方案族至少 3 个。
5. **权项写死尺寸** → 违反 §5.1，退回重写。
6. **把底稿当交付物给用户** → 不合格。用户只该拿到五册；底稿里含方案族、检索结论、淘汰项，
   交出去等于把没申请的那几条和判断口径一起送人（既可能被抄，也可能被反向蒸馏）。
7. **交付稿残留过程痕迹** → 不合格。方法名 / "方案一" / "检索表明" / 取舍措辞 / 【待填】
   一律不得进五册，`audit_lite.py` 的 L 类必须 0 ERROR。

## 12. 与现有体检的衔接

| 阶段 | 用什么 |
|---|---|
| 构思 | 本文件 + `scripts/make_idea_report.py`（骨架 + `--check`） |
| 成稿 | SKILL.md 第二~七章（结构/句式/标号/附图/版式） |
| 体检 | `audit_lite.py`（L0）/ `audit_patent.py` + `audit_exam_risk.py`（L1） |

**构思报告选中的方案进说明书后，必须重新过 J1~J18**：尺寸自洽、权项引用合法、摘要 ≤300 字、权项得到说明书支持、融合差值与样本量匹配（J15）、校验类从权不从属于分段限定（J16）、独权留有必要技术特征（J17）。构思阶段说得通，不等于成稿阶段站得住。
